### Грабли и решения

- `..`-пути GetChild не работают от корневого актора → общий корень "DragonDefense".
- Тела методов JS-классов — strict mode: `DRAGON_GAME = this` бросал ReferenceError →
  `globalThis.DRAGON_GAME`.
- Младшие биты LCG циклятся: `% 4` давал всегда танков → взяты старшие биты.
- Равные drawDepth в слое сортируются недетерминированно: часть лейблов/баров рисовалась под
  панелями → явные drawDepth для виджетов, отдельные слои FXBar/FXBarFill для мини-баров
  (у ImageComponent нет SetDrawingDepth из JS).
- `Scene::FindActor` — по пути от корней, не рекурсивный поиск.
- `SaveBootstrapScene` требует `UpdateAddedEntities()` перед `Save` (иначе пустая сцена).

### WASM: зависание на старте (FPS 0) — багфикс движка

- Репро в headless Chrome (SwiftShader WebGL) + CDP: рантайм wasm абортился C++ исключением в
  `Label::SetText` из `DragonGame.UpdateHud` при старте → main loop мёртв, FPS 0.
- Причина — баг BrowserJS-бриджа движка (`o2/Framework/Sources/o2/Scripts/BrowserJS/BrowserJSCore.cpp`):
  `o2js_get_string_length` возвращал `v.length` (UTF-16 code units), а `o2js_string_to_buffer` пишет
  UTF-8 байты. Для кириллицы буфер оказывался мал, строка резалась посреди мультибайтовой
  последовательности, `utf8::utf8to16` кидал исключение; wasm собран без исключений → abort.
  На QuickJS (десктоп) бридж другой — потому не проявлялось.
- Фикс: длина считается в UTF-8 байтах (`s.enc.encode(v).length`).
- Проверка: игра под WASM управляется через CDP — замок → «В БОЙ» → merge кликами, FPS ~100,
  консоль чистая; скриншоты `Work/ScreenShots/2*_wasm_*.png`. Автотеста нет — WASM-тесты
  в ctest не собираются (O2_TESTS выключен под Emscripten), гэп отмечен.
- Нативные тесты после фикса: 327/327 зелёные (BrowserJS компилируется только под Emscripten).

### Визуальный проход (по фидбеку владельца)

- **Шрифт**: Google Fonts Philosopher-Bold (OFL, кириллица) → `Assets/DragonDefense/Fonts/`;
  все тексты HUD/UI и капшены кнопок на нём; крупные сообщения с тенью (второй Label).
- **9-slice UI**: сгенерированы `panel9` (тёмный камень, тонкая золотая рамка), `button9`,
  `bar_frame9`/`bar_fill9`; всё через `SpriteMode::Sliced` + `sliceBorder`. Прогресс баров —
  изменением ширины fill-виджета (сохраняет скругления), не Fill-режимом.
  Первая итерация панелей была с толстыми рамками — по фидбеку перегенерированы с тонкими.
- **Нижние панели**: контент центрирован (заголовок по центру, ряды кнопок посчитаны от центра),
  заряды бустеров — бейджи на кнопках, «Монеты» — в панели покупки.
- **Сетка поля**: подложки клеток удалены. Первая версия синтетической перспективы не совпадала
  с плиткой фона (фидбек) → пол перегенерирован гладким (edit_image), игровая сетка 7×10
  **запечена в фон** тем же набором формул (`bake_grid.py`): гравировка + лёгкая шахматка,
  в зоне неба бледнее. Юниты попадают в клетки по построению. Формулы (kCell=80, низ -256,
  высота ряда 56-row, сужение 0.024/row) синхронизированы: DragonLayout.h ⇄ DG_LAYOUT ⇄ bake.
- **Подсветки**: пульсирующий глоу под юнитами с доступным слиянием; hover-прицел бустеров
  (бомба — красный 3×3 за курсором, рокировка — зелёный по юниту + жёлтый на выбранном).
  Грабли: (1) равные drawDepth → части HUD рисовались под панелями (явные depth + слои
  FXBar/FXBarFill); (2) SetEnabled(false→true) на свежесозданном акторе в том же кадре теряет
  drawable в слое — пулы прячутся прозрачностью; (3) слабый глоу не читался на камне — усилен.
- **Эффекты боя**: снаряды-кометы (лучник/маг/дальнобойный дракон, поворот по направлению),
  искры на попаданиях/камнях, красные флеши получивших урон, глоу-вспышки (смерть дракона,
  бомба, пожар, прорыв к замку, аура лекаря); мини-HP-бары видны только у раненых.
- **Анимация мержа**: вью поглощаемого юнита летит в целевую клетку (переиспользование актора
  через consumedId из модели), вспышка + искры + scale-пульс результата; каскад анимируется цепочкой.
- Проверка: 327/327 нативных тестов, WASM пересобран (ассеты WebAssembly + Game.data),
  CDP-прогон: замок → бой → merge кликами, ошибок нет; скрины `1*_*.png` (натив), `2*_wasm_*.png`.
